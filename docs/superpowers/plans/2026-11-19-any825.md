# ANY-825 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Monthly server quota and a single verified-email bonus with usable exhausted-state UI.
**Architecture:** PostgreSQL serializes quota, reservations and unique email claims; SMTP delivers verification codes; existing background messages connect the shared popup/sidepanel UI.
**Tech Stack:** FastAPI, SQLAlchemy/PostgreSQL, Redis abuse throttle, React/WXT.
**Spec:** `docs/superpowers/specs/2026-11-19-any825-design.md` (approved by user).

## Global Constraints
- Base 50/month; verified bonus 50, once per normalized email and installation.
- Moscow midnight, installation calendar anniversary; no daily cap, no rollover.
- Errors/cancellation do not consume quota; server enforces concurrent exhaustion.
- Preserve last result, library, copy/insert/save at zero quota.
- SMTP secrets supplied at deployment; no production verification bypass.

## Review Focus
- Parallel last-slot requests and simultaneous email claims cannot overspend/double-credit.
- Month rollover cannot refund an old reservation into the fresh package.
- Expired verification codes, resend and guessing limits cannot yield credit.
- Temporary minute/provider throttling must not mark monthly quota exhausted.
- Popup close/reopen, sidepanel handoff and renewal restore server state.
