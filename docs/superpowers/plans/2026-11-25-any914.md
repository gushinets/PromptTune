# ANY-914 implementation plan

> **For agentic workers:** Execute inline with superpowers:executing-plans.

**Goal:** Produce and audit a Linux/amd64 backend release candidate with an immutable base and a deployment path that preserves its identity.

**Architecture:** Retain Debian trixie and Python 3.12; pin both build stages to the same official amd64 manifest. Build on ANY-913's dependency updates. Record the actual image and installed OS/Python packages, then deploy the saved image by its content ID without rebuilding.

**Tech Stack:** Docker, Compose, Trivy 0.76.2, Debian Security Tracker, pytest.

**Spec:** https://linear.app/paveldik/issue/ANY-914

## Global constraints

- Target production architecture: linux/amd64.
- No production rollout or changes to real environment secrets.
- No vulnerability suppression; remaining High/Critical need component-specific applicability and a release decision.
- ANY-913 is merged into main at b26a78f; ANY-914 is rebased onto that commit.

## Review focus

- A tag changing between scan and deploy must not change the released image.
- Migrations and API must use the same image.
- A wrong-architecture image must fail before rollout.
- Existing source deployment must retain its behavior.
- No production credentials may enter images or retained evidence.
